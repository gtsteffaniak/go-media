# H.264 intra decode (clean-room)

Production thumbnails use **`internal/h264/cleanroom`**: ITU-T H.264 decode with ffmpeg/openh264 as behavioral references. The mgvs/go-openh264 BSD-2 lineage is documented in `THIRD_PARTY_NOTICES.md`. Hot numeric work is in **`internal/kernels/h264`** (portable Go + optional `GOEXPERIMENT=simd` bodies — see [SIMD.md](SIMD.md)).

**Profiles:** Baseline (CAVLC), Main/High (CABAC). Fast thumbnail path skips in-loop deblock (`SkipDeblock`); parity tests can run full deblock.

## Layout (`internal/h264/cleanroom`)

| Area | Role |
|------|------|
| `bitstream/` | RBSP reader, fast `peekBitsMSB` window |
| `decode/` | Slice/MB orchestration, CAVLC/CABAC residuals, predict, transform |
| `decode/cavlc_lut.go` | 16-bit prefix LUTs for coeff_token, total_zeros, run_before |
| `nal/` | Annex-B / EBSP |

DSP helpers: predict-into-plane and in-place residual add for I_16×16 luma/chroma; int32 dequant fast path with saturation.

## Baseline gate vs ffmpeg

Baseline is **enabled** (bit-exact vs ffmpeg: `TestBaselineCAVLCMatchesFFmpeg`). The compare harness lifts profile restrictions; rows stay `performance:` when decode works but misses the in-process timing gate (`expectations.json`, currently **50%** vs ffmpeg).

Policy in `test/compare/expectations.json` (`goarch` per case):

| GOARCH | `mp4_h264_baseline_1080` thumbnails | Notes |
|--------|-------------------------------------|--------|
| **arm64** | `supported` | Within timing gate. |
| **amd64** | `supported` (large); small often ~+55–65% vs ffmpeg | Decode bit-exact; **large** within the 50% gate; **small** still needs more CAVLC/bitstream work to match ffmpeg’s ~45 ms end-to-end. |

**Production / gate build:** `CGO_ENABLED=0` + `-pgo=default.pgo` (compare tier 2; [PROFILING.md](PROFILING.md)).

### Reproduce

```bash
CGO_ENABLED=0 go test -run=^$ -bench=BaselineThumbnail -benchmem ./internal/h264/
make compare-gate
make ceiling-profile   # Baseline decode-only pprof (see below)
```

## Where time goes (Baseline decode)

On Intel Core Ultra 7, `GOMAXPROCS=1`, `BenchmarkBaselineThumbnailDecode` (~47–49 ms/op after recent bitstream tweaks, 1080 Baseline IDR):

| Area | ~cum % | Symbols |
|------|--------|---------|
| CAVLC / MB syntax | **~85–87%** | `residualBlockCAVLC`, `readLevelsInto`, `peekBitsMSB` |
| IDCT + kernels | **~10–11%** | `inverseTransform4x4`, in-place luma/chroma add |

A 2× IDCT speedup is only ~5% end-to-end on this fixture — **optimize CAVLC/bitstream first** for the Baseline gate. Main/High thumb time is dominated by CABAC (~39% of full `Generate` on reference profiles in [PROFILING.md](PROFILING.md)).

Thumbnails **area-downscale** full decoded planes; aggressive presets use **RGB tile average** in `internal/thumb` (`scaleYCbCrArea` + `yccAreaAvgRGB`, no 1080p RGBA prescale). Repeated MP4 thumbs can cache probe via `isobmff.OpenH264MP4Thumb`. There is no crop-only MB skip without changing pixels vs ffmpeg.

## CAVLC optimizations (in tree)

- 16-bit prefix LUTs (no per-decode `map` lookups on hot VLC).
- Batched trailing-one signs in `readLevelsInto`; `run_before` skipped when `zerosLeft == 0`.
- Coeff scratch zeroed before each block parse (bit-exact).
- `ReadUnaryPrefix` uses `bits.LeadingZeros32` on 16-bit peeks (Exp-Golomb / `level_prefix`).

Further levers: level parsing, coeff batching, overlapping entropy with recon — profile after each change (`make bench-micro`).
